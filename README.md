# 📝 Banking Management System

## 📌 Overview

This project demonstrates a **Banking Management System** developed using SQL to organize and manage banking-related information. The database includes customers, accounts, transactions, branches, employees, and loans.

The project focuses on relational database design and SQL queries to retrieve, filter, analyze, and manage banking data. It demonstrates concepts such as aggregate functions, joins, subqueries, set operations, and stored procedures.

---

## 🎯 Objectives

- Design a relational database for banking operations.
- Store and manage customer and account information.
- Retrieve customer details using SQL queries.
- Analyze account balances using aggregate functions.
- Connect related tables using JOIN operations.
- Use subqueries to solve data retrieval problems.
- Combine results using UNION.
- Implement stored procedures to retrieve customer details.

---

## 📊 Database Description

The database consists of six main tables:

| **Table** | **Description** |
|---|---|
| `customers` | Stores customer details such as name, address, phone, email, and date of birth. |
| `accounts` | Stores account types, balances, customer references, and branch references. |
| `transactions` | Records account transactions, amounts, types, and dates. |
| `branches` | Stores branch names and locations. |
| `employees` | Stores employee names, designations, salaries, and branch references. |
| `loans` | Stores loan amounts, loan types, interest rates, and related dates. |

---

## 🛠️ Tools & Technologies Used

- **SQL** – Database creation and data manipulation
- **MySQL** – SQL query execution and database management
- **Relational Database Concepts** – Tables, primary keys, and foreign keys
- **Aggregate Functions** – COUNT(), SUM(), AVG(), MAX(), and MIN()
- **SQL Joins** – INNER JOIN and LEFT JOIN
- **Subqueries** – Nested queries for data retrieval
- **Set Operations** – UNION
- **Stored Procedures** – Reusable SQL routines

---

## 🧪 Methodology

### 1. Database Design

- Organize banking information into separate relational tables.
- Define primary keys and foreign keys.
- Establish relationships between customers, accounts, branches, employees, transactions, and loans.

### 2. Data Retrieval

- Display customer names, phone numbers, and email addresses.
- Filter customers based on their location.
- Retrieve accounts based on account type and balance.

### 3. Data Analysis

- Calculate the highest and lowest account balances.
- Count accounts grouped by account type.
- Compare account balances with the average balance using subqueries.

### 4. Joining Tables

- Retrieve employee details along with branch information.
- Connect customer records with their accounts.
- Combine information from multiple related tables.

### 5. Set Operations

- Use UNION to combine customer and employee names into a single result set.
- Eliminate duplicate rows when required.

### 6. Stored Procedures

- Create a stored procedure to retrieve customer details based on a customer ID.
- Use an input parameter to make the procedure reusable.

---

## 📈 Results & Analysis

The project demonstrates how SQL can be used to organize banking data and retrieve meaningful information from related tables. Aggregate functions help analyze account balances, joins connect information across tables, and subqueries support comparisons with calculated values.

The project also demonstrates how UNION combines result sets and how stored procedures can simplify repeated database operations.
